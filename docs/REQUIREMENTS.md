# System Requirements Specification (SRS)

## 1. Functional Requirements (FR)

### FR-1: User Management & Authentication
- **FR-1.1**: Users must be able to register using email/password or OAuth 2.0 (Google, GitHub).
- **FR-1.2**: Passwords must be hashed using Argon2id or bcrypt prior to storage.
- **FR-1.3**: Authenticated sessions must issue stateless JWT access tokens (15m expiry) and HTTP-only refresh tokens (7d expiry).
- **FR-1.4**: Users are assigned roles: `STUDENT`, `TUTOR`, or `ADMIN`.

### FR-2: Collaborative Study Rooms
- **FR-2.1**: Students must be able to create public or password-protected private study rooms.
- **FR-2.2**: Study rooms support synchronized real-time vector whiteboards, text chat, and active participant presence.
- **FR-2.3**: Synchronized Pomodoro timer allows room owners to start, pause, and reset study sessions for all room members.

### FR-3: AI Gateway & Study Assistant
- **FR-3.1**: Students can request smart note summaries by providing raw text, markdown, or transcripts.
- **FR-3.2**: AI Gateway must execute prompt requests against the primary OpenAI model (`OPENAI_MODEL`) and automatically fail over to Gemini (`GEMINI_MODEL`) on errors or timeouts (> 5s).
- **FR-3.3**: Quizzes generated by AI must contain 3-10 multiple-choice questions with answer keys and explanations.
- **FR-3.4**: All AI queries are cached in Redis with a 24-hour TTL based on prompt hashing.

---

## 2. Non-Functional Requirements (NFR)

### NFR-1: Performance & Scalability
- **NFR-1.1**: API response latency (p95) must remain under 200ms for non-AI endpoints.
- **NFR-1.2**: WebSockets message delivery latency must remain under 50ms.
- **NFR-1.3**: Redis cache hits for AI queries must return response payloads within 20ms.

### NFR-2: Security & Compliance
- **NFR-2.1**: All client-server communications must use TLS 1.3 / HTTPS.
- **NFR-2.2**: API input payloads must be strictly validated against Zod schemas.
- **NFR-2.3**: Sensitive secrets must never be logged or exposed in client bundles.

### NFR-3: Availability & Fault Tolerance
- **NFR-3.1**: 99.9% uptime target for API Gateway.
- **NFR-3.2**: Database connection pooling configured via Prisma Accelerate or PgBouncer.
